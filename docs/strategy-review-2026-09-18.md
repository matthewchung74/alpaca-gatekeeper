Gatekeeper strategy review — September 18, 2026

The strategy has useful controls, but its trading edge is still unproven and several execution paths weaken the protection those controls promise. Repair the exit and accounting problems before using results to tune the strategy. Then compare a few frozen alternatives at equal risk.

Priority findings follow. P1 means address before relying on the automated controls or deploying capital; P2 means materially misleading accounting or strategy measurement.

1. **P1 — The daily “flatten + halt” is not implemented.** `agent/config.py:45` promises it, but `agent/risk.py:66` only rejects a new proposal. Exit sweeps return before entry gates (`agent/loop.py:285`); existing spreads are closed only by their individual exit rules. The caller never supplies a persisted `halted` state, so a recovered account can become eligible again. Daily starting equity is the first observed mark, which excludes an overnight loss before that mark. Both journal backends also omit the account profile when selecting that baseline (`agent/journal.py:200`, `agent/journal_firestore.py:146`). Add an account-specific ET session baseline, a persisted daily halt, and an account-level exit path checked on every sweep. Define explicitly whether overnight changes belong in the daily limit. The 15% threshold is a loss from a fixed $100,000, not a drawdown from the account's high-water mark.

2. **P1 — A zero bid on the protective option disables normal exits.** `agent/manage.py:70` passes the long bid through `_f`, which rejects zero (`:166`). Reproduction: a $0.50 entry credit, short ask $1.50, and long bid $0 produces `mark=None` and `hold`; valuing the long conservatively at zero gives a $1.50 close cost, exactly the stop. Distinguish a valid zero bid from missing/stale data, and preserve an executable exit path when the protective option becomes worthless. Separately, bid/ask extremes can trigger a stop just because liquidity widened. Record midpoint, executable estimate, quote age, and actual fill to diagnose those cases.

3. **P1 — Broker exposure can escape the journal's management.** An entry still unsettled after cancellation explicitly returns with a possible unjournaled position (`agent/loop.py:402`). Subsequent management only visits journaled spreads. A timeout or process failure between submission and recording creates the same class of risk. Conversely, a missing short leg is treated as “not yet filled” (`:145`), even when assignment or broker liquidation removed it. `held_qty` checks only the absolute short-leg quantity, not its sign, the matching long quantity, or allocation across journal rows (`agent/manage.py:24`). Persist order intent before submission, recover pending orders on restart, reconcile both legs and stock positions, and block additional entries while exposure is unexplained. The code also lacks a shared account lock, while new UUIDs on each invocation do not make retries idempotent across jobs.

4. **P1 — Calendar and assignment handling leave gaps.** `agent/manage.py:88` assumes a 16:00 close and only recognizes assignment risk on expiration day. The calendar helper exists but is unused. On an early-close session, a 15:30 flatten is too late. Entry lockout rules also suppress exit sweeps in the first/last five minutes (`agent/loop.py:247`). Use actual exchange session times, distinct entry/exit windows, and dividend/early-assignment handling. Alpaca documents that short calls in spreads can be assigned around ex-dividend dates and create short stock plus dividend obligations: [Alpaca dividend risk](https://alpaca.markets/support/what-is-options-dividend-risk).

5. **P2 — Partial closes can produce false realized P&L.** The incomplete-close branch records neither realized proceeds nor remaining journal quantity (`agent/loop.py:212`). When the remaining broker quantity eventually closes, `sp.realized_pnl` uses the original journal quantity at the last exit price. A fully mocked reproduction closed 4 of 10 contracts at $1.50 and the other 6 at $2.00, against a $0.50 entry: actual gross P&L −$1,300; recorded P&L −$1,500. Store each fill, accumulate realized P&L, and decrement remaining quantity. This is a demonstrated failure mode, not evidence that a particular historical trade was misrecorded.

6. **P2 — Directional risk is not a portfolio loss estimate.** `agent/risk.py:324` subtracts put-spread maximum loss from call-spread maximum loss. Reproduction: a $900-risk put wing and a $900-risk call wing report $0 directional risk. Even a same-expiry, same-underlying condor with $100 credit per wing still loses $800 in either tail. Different underlyings, expirations, and stop-outs weaken the cancellation further. Keep the gross book cap and add separate upside/downside scenario losses; only net positions using actual payoff relationships. The global book cap also uses the proposed ticker's regime (`agent/loop.py:324`, `agent/risk.py:460`), so a sideways ticker can admit risk beyond the cap a bearish ticker would impose on the same book. Give the portfolio a stable, separately defined budget.

7. **P2 — The liquidity gate accepts invalid or old markets.** `agent/risk.py:215` checks positive prices and relative spread width, but not crossed quotes, freshness, or displayed size. Missing OI passes. A reproduction using crossed quotes timestamped in 2020 and absent OI passed. Quotes, equity, and the cycle timestamp are captured before the model call and never refreshed before submission. Validate market data, calculate spread-level transaction cost relative to expected profit, and refresh account/quote state immediately before the final gates. A binding limit constrains execution price; it does not validate stale regime, exposure, or entry timing.

The main strategy questions are broader than the implementation findings:

- **Exit economics are demanding.** With entry credit C, the 50% target earns 0.5C. A buyback at 3C loses 2C, when the width cap does not bind. Four target winners offset one stopped loser; the two-outcome break-even win rate is 80% before costs. Actual fills, time exits, gap losses, and different position sizes change this, so measure actual average win/loss. The historical competition averages imply about 65% break-even, which explains that comment in the configuration; it should not be assumed for the revised strategy.
- **Sizing still reflects the tournament.** A 12% single-trade and 24% book maximum loss can exceed the intended 4% daily and 15% event thresholds before a stop executes. Two full-sized maximum losses compound to a 22.56% decline. For research, a fixed 0.5–1% maximum loss per trade and 3–5% gross book budget would make comparisons easier and reduce the cost of finding bugs. These are conservative starting budgets, not optimized parameters or claims of improved expectancy.
- **Distance from price is not a demonstrated pricing edge.** Delta, an expected move, and the recent range describe strike placement. They do not show that the credit received exceeds the expected losses and costs. The strategy has no explicit test of whether implied volatility is rich relative to a forecast of realized movement. Published put-writing evidence motivates studying volatility risk premium, but does not validate these particular ETF verticals: [Cboe research overview](https://www.cboe.com/insights/posts/white-paper-shows-volatility-risk-premium-facilitated-higher-risk-adjusted-returns-for-put-index).
- **The regime rule mixes trend and mean reversion with abrupt boundaries.** A small move across a threshold can switch eligible sides and change per-trade risk from 12% to 4.2%. Old observations dropping out of the ten-session window can do the same. The most recent revision relaxes the range restriction specifically because recent trades were blocked; that may help feasibility but has not established better returns. Log how many genuinely executable candidates each gate rejects, then evaluate filters individually on later data.
- **Macro risk remains a prompt instruction.** FOMC dates are supplied, but CPI/PCE calendars and deterministic event budgets are absent. “First Friday” is not a reliable payroll calendar for all months. Use published schedules and a known update policy: [BLS 2026 calendar](https://www.bls.gov/schedule/2026/). Event avoidance should be tested as a strategy choice; market holidays and dividend handling are operational requirements.
- **LLM selection has no measured incremental value.** Code determines most eligibility, but the model still chooses ticker, width, requested credit, and quantity. Build a deterministic list of feasible spreads and size them consistently; compare a fixed selection rule against model selection from that same list. Include inference cost and latency. The two sleeves were also not inherently opposing exposures: put credit plus call debit are both bullish. Keeping the satellite disabled is a reasonable research constraint, not proof from four losses that debit spreads cannot work.

A focused experiment plan, after the P1 fixes:

| Experiment | Variants | What it tests |
| --- | --- | --- |
| Model contribution | Deterministic selection vs model ranking of the same feasible candidates | Whether discretionary selection adds net value |
| Holding horizon | Current nearest expiry at least 7 days away vs 14–21 DTE | Whether more time reduces stop churn enough to justify slower capital turnover |
| Exits | 50% vs 75% credit capture; 2C vs 3C close-cost stop | The whole win/loss distribution, rather than improving the nominal ratio alone |
| Strike/regime filters | Delta baseline; add expected-move filter; then range/regime filters | Whether each restriction contributes beyond lower trade frequency |
| Volatility/events | Baseline vs a predefined volatility-richness filter; separately test scheduled-event restrictions | Whether entry conditions improve compensation for risk |

Run these sequentially with fixed sizing and a small, declared set of parameters. Avoid searching every combination and selecting the best-looking result. Use actual historical option quotes and the same intraday management cadence; underlying bars alone cannot establish which exit fired first or which spread price was executable. Include spread costs, fees, gaps, missed fills, inference cost, and simultaneous portfolio positions. Freeze parameters before evaluating later time periods, and use confidence intervals that preserve dependence between trades in the same week. Report average P&L per unit of maximum risk, average win/loss, drawdown, worst week, turnover, and candidate/rejection counts.

Paper fills should be treated as execution simulations. Alpaca says they omit latency slippage and queue position, and do not constrain fill size to quoted NBBO quantity: [Alpaca paper-trading limitations](https://docs.alpaca.markets/us/docs/paper-trading).
